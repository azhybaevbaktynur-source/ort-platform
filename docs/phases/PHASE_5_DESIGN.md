### 3.1 `0006_phase5_cutover` (down_revision `0005_phase4_grading`) — slice S1

1. `create_table legacy_ort_export`: `exam_set_id String(64) PK, language String(2), exam_type String(16), title Text, description Text, sections JSON, max_attempts Integer, available_from/available_until String(40), source_id String(120) null, question_count Integer, payload JSON, exported_at tstz, consumed_at tstz null, result JSON null` (JSONB on PG). 2. Export: for each `exam_sets` row with ≥1 question (`questions.exam_set_id = e.id` OR `e.question_ids` contains the id; production: only the coomo set), insert one export row. `payload` = ordered list of `{section, topic, difficulty, stem, column_a, column_b, option_a..e, correct_option, passage_text, explanation, image_url, tags, position, q_num, external_id, fixed}` ordered by ORT section order (`math_1, math_2, analogies, reading, grammar, subjects…`), then `position NULLS LAST`, then `created_at, id`; `question_sources` joined on `question_id` for `external_id/q_num/fixed`; `source_id` = the set's single `question_sources.source_id` or `legacy_<exam_set_id>`. `ON CONFLICT DO NOTHING` on the PK. Empty sets are not exported (the 19 shells vanish; `result` of the seed logs them as `skipped_empty_exam_sets`).
3. `UPDATE users SET is_platform_admin=true, teacher_status='approved' WHERE role='admin'` (defensive repeat of 0002).
4. Drops, FK order: `question_sources` → `test_attempts` → `exam_access` → `questions` → `exam_sets`.
5. `users`: `op.batch_alter_table("users")` drop `role, target_score, exams_taken, current_score, starting_score`. **SQLite batch concern**: the table recreate must carry the self-FK `fk_users_disabled_by_id_users`, the three named CHECKs and `ix_users_teacher_status`; pass `naming_convention=NAMING_CONVENTION` and `recreate="always"` on SQLite, and assert the constraint names after upgrade in `tests/test_migration_0006_data.py` (pattern of `test_migration_0005_data.py`). ## 6. R2 free-tier guard (slice S4; owner req. 8)

- Settings: `STORAGE_WARN_BYTES = 8 GiB`, `STORAGE_HARD_BYTES = 9.5 GiB`, `ASSET_MAX_UPLOAD_BYTES = 2 MiB`, `FILE_MAX_UPLOAD_BYTES = 10 MiB`, `FILE_ALLOWED_MIMES = ["application/pdf"]`.
- Accounting (`app/lms/files/usage.py`): `record_written(db, bytes, objects=1)` = `UPDATE storage_usage SET stored_bytes = stored_bytes + :b, object_count = object_count + :n` + upsert of the current `storage_monthly_usage` row (`class_a += 1` per PUT, `class_b += 1` per HEAD/GET the backend itself makes, `bytes_written`, `objects_written`). Called in `files/service.py` right after a **new** blob is stored (`ingest_image` new-blob branch, `store_new_blobs` for imports, the new `ingest_file`); dedup hits write nothing. `check_capacity(db, add)` runs before storing: `stored_bytes + add > HARD` → `StorageFull` (HTTP 507, code `storage_full`, details `{stored_bytes, limit_bytes}`); `check_import_caps` gets the same check. Single-row contention: uploads are rare (≤ 300/h/user) — acceptable; attempts never touch it.
- Decrement: `delete_unreferenced_blobs` / `sweep_orphan_blobs` subtract only when the driver actually deleted (local/db). On r2 nothing is deleted or listed (`old_keys()` → `()`), so the counter is "bytes ever written" (P5-11).
- PDF files: `POST /courses/{course_id}/files` (same streaming cap pattern as `upload_asset`, cap `FILE_MAX_UPLOAD_BYTES`; `%PDF-` magic + `Content-Type` ignored; sha256 of raw bytes; key `priv/{sha}.pdf`, `_KEY_RE` extended to `^(img|priv)/[0-9a-f]{64}\.(webp|pdf)$`; `Asset(kind='file', visibility='private', mime='application/pdf', extension='pdf')`; per-owner dedupe; user quota + `check_capacity`). Download via the existing `GET /assets/{id}/content` (owner only; r2 → presigned 302 with `ResponseContentType=application/pdf`). No UI yet (Phase 6 pages reference files). Route policies added.
- Public URLs: unchanged `media_url()` — with `LMS_STORAGE_DRIVER=r2` and `R2_PUBLIC_BASE_URL` set every image URL is `{R2_PUBLIC_BASE_URL}/img/{sha}.webp`; the object carries `Cache-Control: public, max-age=31536000, immutable` at PUT. Add a startup log line stating which base is in use and a `storage` block in `/health`? **No** (`/health` is public): put it in the admin summary instead.
- Admin: `GET /platform/storage` (policy `platform_admin`): `{driver, public_base_is_r2dev, stored_bytes, object_count, warn_bytes, hard_bytes, level: ok|warn|full, month: {class_a, class_b_backend, class_b_estimated, bytes_written, objects_written}}` where `class_b_estimated = Σ over assessment versions used this month: attempts_started_this_month(version) × image_refs(version.snapshot)` (one grouped query over `attempts` + a Python scan of the few snapshots). `POST /platform/storage/smoke` (P5-12; rate-limited 5/h; audited `storage.smoke`): result `{put_ok, head_ok, public_read_ok, public_url, status_code, deleted, latency_ms, error}`; refuses when driver ≠ r2 (`storage_driver_not_r2`). `R2StorageService` gets `delete_object_unsafe(key)` used **only** by the smoke check. Frontend `/[lang]/admin/storage` page: numbers, level banner (amber ≥ warn, red = full), smoke button + result; `AdminShell` nav entry; banner also on `/[lang]/admin` when `level != ok`. Keys `storage.*`, error `files.errors.storage_full` (en/ky/ru).
- `docs/CAPACITY_REVIEW.md` § "R2 free tier (Phase 5)": a digitized 150-question ORT exam has ~16 images, stored WebP ≈ 3–30 KB each (tsoomo19: 2.8 KB) → < 1 MB per exam; **storage (10 GB) holds thousands of exams**. Class A: ≤ 2 ops per new image (HEAD counts as B) → irrelevant. **Class B is the limit**: 6,000 students × 16 images = 96,000 public reads per exam sitting (browser cache keeps repeats out) → **about 100 full-size exam sittings per month** within 10M reads; each 1 MB-ish exam adds nothing meaningful to storage. r2.dev has an unpublished rate limit and is the real risk for a 6,000-student burst: custom domain before the first large exam (owner item 4). Neon side unchanged (`attempt_items` ≈ 0.2 GB per 6,000 × 150 exam, PHASE_3.md).
